Pre-launch whole-platform audit on branch `feat/property-dashboard-redesign` (2026-07-12), user acting as PM ("find every bug before we launch"). Baseline was clean: `tsc` 0 errors, jest 114/114, Windcave idempotency / split-payment atomicity / GST rounding / crypto-confirm prod-gating all verified sound.

**Fixed + verified live + committed:**
- **C1 CRITICAL** `cde0ba8` — public `GET /api/merchants/:id` returned the full row via `getMerchant()`'s `SELECT *`: leaked bcrypt `passwordHash`, reset/verification tokens, Windcave+Coinbase API keys, bank/card details. Sequential ids ⇒ whole table harvestable. Added `stripMerchantSecrets()` + `publicMerchant()` in routes.ts; applied to the public endpoint (both) and the two admin endpoints (secrets only). `/api/auth/me` was already a hand-picked `{user}` (safe). Live: 52→37 keys, all 15 sensitive gone, 12 branding fields preserved. Non-breaking (bank/card are write-only onboarding form inputs).
- **C2 HIGH** `fa2807c` — `PUT /api/merchants/:id/business-details` (unauthenticated onboarding step, id from URL) let anyone overwrite any verified merchant's business name/contact email/GST/address. Can't require JWT (pre-login), so gated to the onboarding window: reject if `status==='active' || onboardingCompleted`. Live: PUT on active m22 now 403s, unchanged.
- **C4 MEDIUM** `54d7d53` — refund route was check-then-act (read refundable → Windcave → update totals, no lock); double-clicked/concurrent refund over-refunds (merchantReference has Date.now() so gateway won't dedupe). Added atomic `reserveRefundAmount()` (guard: `price - totalRefunded >= amt`) before the gateway call + `releaseRefundAmount()` rollback on failure. Mirrors `atomicClaimSplitShare`. Live: 2 concurrent full refunds on $15 txn → one 200 + one 409, totalRefunded settles $15 not $30.
- **C5 MEDIUM** `cc07584` — `POST /api/internal/cron` had no overlap guard; concurrent/overlapping runs double-generate invoices + double-dispatch emails (generate/dispatch fetch-then-write, advance nextRunDate non-atomically). Added in-process `cronRunning` lock (409 + try/finally). Single-instance-appropriate. Verified by inspection + tsc (CRON_SECRET unset in dev).
- **C3 MEDIUM** `94dadd8` (option b, user-chosen) — `GET /api/merchants/:id/events` (SSE) was unauthenticated + broadcast the FULL transaction to any subscriber of a merchantId → cross-tenant live sales feed incl. `merchantNet`/fee rates (BI leak; no customer PII — transactions table has none). Can't require auth: the **anonymous customer-payment page depends on this stream** (`customer-payment.tsx:82`). Dual-payload fix: merchant terminal now passes JWT in the query string (EventSource can't set headers) → endpoint tags conn `__sseAuthed` when token matches merchant/admin; `sseWrite()` sends full to authed, `publicSseData()`-redacted (strips fee/margin internals + processor ids + refund) to anonymous. `sse-client.ts connect()` gained an optional token arg; `merchant-terminal-mobile.tsx` passes it, `customer-payment.tsx` doesn't. Verified live: anon SSE lacks windcaveFeeRate/platformFeeRate/merchantNet, authed has them.

**Verified clean (no bug):** property+trades `:id` resource routes — 29 routes, all enforce ownership (`checkMerchantOwnership`→403 or inline `merchantId!==`→404); crash hardening intact (port-manager.ts unhandledRejection logs & never exits, uncaughtException dev-survives). Unguarded `parseInt(req.params)` mostly benign (NaN→404); LOW hygiene item.

Dev server = `tsx server/index.ts` (NO watch) under a `while true` supervisor; to load server changes `pkill -f "tsx server/index.ts"` and the supervisor relaunches (~2s).
