## Three Final Notes

**First**, the `last_reminder_sent_at` timestamp on invoices_rent_requests is mentioned in the Phase 1 schema step, which is correct — but make sure the 24-hour cooldown check in the Send Reminder API (Phase 3) compares against this field using the merchant's local timezone, not UTC. A reminder sent at 11 PM NZ time shouldn't become re-sendable at midnight UTC.

**Second**, the plan mentions SSE broadcast to the landlord when a payment completes. Make sure the SSE connection is scoped to the merchant's session — you don't want payment events leaking across merchants. This is probably already handled by the existing SSE infrastructure, but worth verifying during Phase 2.

**Third**, the CSV import's "single atomic transaction per row" is the right approach (one bad row doesn't roll back the whole file), but make sure the dry-run preview and the actual commit use the same validation logic. If the preview says "24 rows valid" and the commit then rejects 3 of them due to a stricter code path, landlords will lose trust in the import tool.
