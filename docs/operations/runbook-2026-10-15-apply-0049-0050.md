# Runbook — apply migrations 0049 and 0050 to the test database (owner), 2026-10-15

For Oliver. Applies `0049_retail_identity_hardening.sql` and `0050_decline_supersession.sql`
to the **test/development** database only, never production. Claude cannot do this from its
cloud session: it has no database credentials, and applying migrations to a shared database is
an owner step.

**Do this after 0034–0048 are applied** on the same database (the
[0034–0038 runbook](runbook-2026-10-13-apply-0034-0038-test-database.md), Codex's R3 release for
0039–0047, then the [0048 runbook](runbook-2026-10-14-apply-0048-refund-operations.md)), and
**before the R3 build first boots** on it. The R3 build reads and writes the columns 0050 adds,
so payment reconciliation fails on a database without 0050. Then run the
[R3 cutover gate](runbook-2026-10-15-r3-cutover.md).

Read-only commands come first. Step 4 is the only one that changes the database. Everything
runs from the TaptPay Replit shell, where `DATABASE_URL` is already set as a secret. Never
paste a database URL or password into a chat, a command line or a file.

## What they do

- **0049** ([open items](../evidence/remediation-v2-2/r4/R3-OPEN-ITEMS-2026-10-15.md)):
  - An attached or finished retail attempt can no longer be given a provider account or
    fingerprint for the first time.
  - Send intent is checked in UTC, whatever the database session's time zone.
  - Locks `payment_attempts` briefly.
- **0050** ([T-3 ADR](../decisions/2026-10-15-t3-decline-supersession.md)): a later approved card
  in a Windcave session already recorded as declined is recorded. It adds and backfills
  `payment_settlement_events.provider_transaction_id` from each event's session binding. It then
  adds the supersession rules: the registry, binding and attempt triggers, the event ordering,
  and append-only events. It locks `payment_settlement_events`, `payment_session_bindings`,
  `provider_transaction_claims`, `payment_attempts` and `invoice_payment_attempts` for the
  migration's length.
- The runner limits each lock wait to 5 s and each statement to 60 s. **Stop the app first.**

## 0. Get the code

```bash
git fetch origin ccr-e07e3100-0wm8kr
git checkout ccr-e07e3100-0wm8kr
git pull --ff-only origin ccr-e07e3100-0wm8kr
npm ci
TARGET="--target=workspace --expected-host=helium --expected-database=heliumdb"
```

(Use the staging variant from the 0034–0038 runbook, step 1, if your test database is Neon.)

## 1. Back up first

Take a backup or snapshot of the test database with Replit's database tools.

## 2. Look before changing anything (read-only)

```bash
npm run db:migrate:status -- $TARGET
npm run db:release -- $TARGET --dry-run
```

Expected: only 0049 and 0050 pending. Paste both outputs to Claude.

## 3. Count-only preflight (read-only)

In the database's SQL console:

```sql
-- 0050 refuses to run if any settlement event's binding has no provider transaction (expected 0).
SELECT count(*) AS events_without_transaction FROM payment_settlement_events e
  JOIN payment_session_bindings b ON b.session_id = e.session_id WHERE b.provider_transaction_id IS NULL;
-- Sizes of the tables 0050 locks.
SELECT (SELECT count(*) FROM payment_settlement_events) AS events,
       (SELECT count(*) FROM payment_session_bindings) AS bindings,
       (SELECT count(*) FROM payment_attempts) AS retail_attempts,
       (SELECT count(*) FROM invoice_payment_attempts) AS invoice_attempts;
SHOW TimeZone;
```

Paste the results to Claude. **Stop** if `events_without_transaction` is not 0, or if any count is
unexpectedly large (more than a few thousand): the lock time must then be measured on a restored
copy first.

## 4. Apply (changes the database)

With the app stopped:

```bash
npm run db:release -- $TARGET
npm run db:migrate:status -- $TARGET
```

Expected: 0049 and 0050 applied, nothing pending. Then run the [R3 cutover gate](runbook-2026-10-15-r3-cutover.md)
before starting the R3 build.

## 5. If something goes wrong

- **A migration fails.** Each runs in one transaction, so a failed one changes nothing. Paste the
  error code (not any values) to Claude.
- **A problem after they apply.** Do not start the R3 build; tell Claude. Restore from the step 1
  backup only if Claude advises it.
