## What changed

- **`migrations/0039_refund_operations.sql`** extends `refunds` into durable refund
  operations:
  - **Columns:** the operation ID, typed state, business-scoped idempotency key and
    fingerprint, X-ID, reference, original capture and share, environment, exact cents,
    provider refund ID, lease, attempt count, next reconciliation time, sanitized error code,
    the user and reason, and timestamptz timestamps.
  - **Rules:** the shape CHECKs; one trigger enforcing the state graph, identity, the
    tenant/user/capture check, the freeze and the delete guard; and six indexes.
  - **Legacy rows** (state null) are untouched, apart from gaining an operation ID.
- **`shared/schema.ts`:** the Drizzle declaration. `insertRefundSchema` omits every
  operation field, so no legacy writer can set one.
- **`server/storage.ts`:** MemStorage legacy refunds carry the new fields.
- **`server/migration-baseline-contract.ts`:** 53 entries for 0039.
- **Tests:**
  - `migrate.test.ts` (migration order);
  - `migration-schema-parity.test.ts` (now covers `refunds`);
  - `r4-t2-refund-schema.test.ts` (new).
- **`scripts/verify-r4-t2-refund-operations-postgres.ts`:** 28 checks on a fresh database,
  with a non-UTC session time zone.

## How it was reviewed

Pass 3 approved revision 1. Then three independent rereads, each by a different read-only
agent:
- **Pass 4:** refused revision 1 (five blockers).
- **Pass 5:** refused revision 2 (two blockers).
- **Pass 6:** approved revision 3, scoped, with five conditions.

This session checked every finding in the code before answering it. Tests were written
before the implementation: the unit tests failed until it existed, and the PostgreSQL
verifier was drafted before the migration.

**Mutation checks.** Each of these deliberate breaks of the SQL fails the verifier:
- the capture check;
- the status mapping;
- an extra arrow in the graph;
- unfreezing the fees;
- the approved-attempt test;
- the CHECK's non-null method;
- the trigger's null-safety.

Removing the trigger's KEY SHARE lock does not fail it, because `refunds`' existing foreign
key takes the same lock (recorded in the ADR).

## Rules R4-T3/T4 must follow (from the ADR)

- **Lock order:** lock the sale FOR UPDATE before any operation row.
- **Send intent:** commit `submitted`, with a lease covering the call and its polls, before
  any provider call. A refused move to `submitted` means do not send.
- **No finishing under a live lease:** a worker never finishes a `submitted` row while its
  lease is live. A 404 is not "not processed" unless Windcave confirms it.
- **One refund ID:** a final reply naming a different refund ID from the pending one is a
  mismatch, and parks the operation.
- **Retire legacy reserve and release entirely.** Check the completed status under the lock.
  Take the environment from configuration.
- **Surface parked rows** to a reviewer.
