## Verification of Prior Fixes

`GET /api/auth/session`, requiring `signedIn: true`, a user and a CSRF token.
The retail fixture, trades fixture and desktop P0's `installMocks` still write
fake JWTs into `localStorage` and answer `/api/auth/me`. Mobile and terminal-dock
inherit the retail fixture. The existing T10c-1 evidence records the resulting
session-fault page; that claim will be independently reproduced before repair.
T10c-2's results remain its own evidence, not an assumed prerequisite pass.

## Blocking Issues

The old fixtures cannot currently establish the session the app reads. Dock's
absent test also creates a signed-in fixture before opening `/login`, then merely
notes and skips an unexpected dock. Both are verification blockers addressed by
this scope. No application defect is established by them. Full desktop P0 needs
a Vite development source server because its assertions inspect `/src/` requests;
a built static app cannot satisfy those assertions.

## High-Risk Concerns

An unconditional signed-in session reply could make public tests inspect a
merchant screen. A 200 alone proves no identity. Preserve separate signed-out
contexts, require the expected synthetic merchant and session reply, and verify
the cookie is present only for protected fixtures. These fixture replies do not
prove server authentication; the T10 matrix keeps its real sign-in coverage.

## Missing Steps

Use one shared fixture helper to install an opaque HttpOnly session cookie and
answer the exact startup endpoint with the existing synthetic user and CSRF token.
Return signed-out when the fixture cookie is absent. Replace the fake JWT and
`/auth/me` setup in retail, trades and P0; preserve mode, merchant ID, rows,
clock and tutorial gates. Give the retail page factory an explicit public optout
and use it for dock's `/login` case. That case must show Login, remain on `/login`
and have no dock; an unexpected dock must fail. Reuse the standardized base URL
and Chromium configuration rather than adding another environment convention.

## Unsafe Assumptions

Layout fixtures are synthetic intercepted replies, not live API or cookie-security
proof. Existing phone baseline allowances may still permit defects; a passing old
gate cannot close T10f. Full P0's source-module isolation checks must remain intact
and dev-tied. Public keyboard contexts already use separate pages and must retain
their signed-out behavior if the shared factory changes.
