How it works, for whoever picks it up:

- A page writes `apiPath("GET /api/merchants/:id/profile", { id })`, or
  `apiRequest(...apiTo("PUT /api/merchants/:id/theme", { id }), body)`. The name is the
  server's own registration. `shared/api-routes.ts` lists the names with each
  parameter's type; it is **generated** (`node --import tsx
  scripts/generate-route-policy.ts` writes it with the policy). Do not edit it.
- `server/__tests__/api-route-contract.test.ts` is both the contract and the guard. Its
  `MIGRATED` list names the files that may no longer spell an API address; a moved file
  is added there in the same commit.
- Tests keep their literal addresses on purpose.
- After changing a route: run the generator, as before; the third file follows.
- Running the generator also rewrites the first line of `server/route-policy.ts` and of
  the two inventory tables (the commit and date). When no route changed, leave those
  three as they were (`git checkout --` them).

## What the audit for T10b found (measured on `9f9182e5`)

Scratch tools, git-ignored, under `.local/claude-scratch/session-2026-10-06/t10b/`:
`audit.ts` (every spelled address, by what it is handed to and which route it is),
`reach.ts` (which files the app can load), `codemod.ts` (the rewrite), `proof.ts` (a
moved file builds the same addresses from the same values and nothing else changed),
`sync-sites.ts` (where a refusal by the builder would not be a rejected request).

- **581 addresses are still spelled by hand, in 66 files.**
- **118 of them are in 14 files the app never loads** (11 that nothing imports, and
  three pages `App.tsx` declares for lazy loading and never renders:
  `merchant-terminal`, `demo-terminal`, `create-merchant`). Every call found to a route
  the server no longer has is in one of these 14: the admin sign-up, edit and delete
  removed on 2026-09-26, `nfc-pay`, `split-enabled`, the old wallet-button routes, the
  admin API-key pages, the old exports. They are listed for the owner; nothing is
  deleted.
- **463 are in the 52 files the app renders.** None calls a route the server does not
  have. 125 are cache keys that are the whole path of a GET route; 79 are cache labels
  (`"/api/merchants"` 70 times, and four others); one is a key built from an id; the
  other 258 are requests.
- A dry run of the rewrite places 410 of the 463 with certainty and leaves 53 to be done
  by hand (17 of them in `lib/payment-addressing.ts`). All 118 of its calls that carry
  a parameter sit inside an async function or a function react-query calls, so a
  refusal by the builder is a failed request there, never an exception while drawing.
