## How the route contract works now

- A page writes `apiPath("GET /api/merchants/:id/profile", { id })`, or
  `apiRequest(...apiTo("PUT /api/merchants/:id/theme", { id }), body)`. The name is the
  server's own registration. `shared/api-routes.ts` lists the names with each
  parameter's type; it is **generated** (`node --import tsx
  scripts/generate-route-policy.ts` writes it with the policy). Do not edit it.
- **The builder never throws.** A value it cannot use (null, zero, a fraction, empty
  text) leaves the parameter's own name in the path, and the server refuses it. So an
  address may be worked out anywhere, including while a page is drawn.
- An id that reaches a page as text where the server reads a whole number goes through
  `wholeNumber(text)`. A cache key whose first word is not itself an address uses one of
  the five labels (`MERCHANTS_KEY` and four others); every key has the value it always
  had.
- `server/__tests__/api-route-contract.test.ts` (43 tests) is the contract. **It holds
  every source file under `client/src`, tests aside**: none may spell an API address.
  The two exceptions are named in the test: 14 files the app never loads, and the admin
  area's own page at `/api`.
- What the test will refuse in a new or changed page: a spelled address; a route name
  that is not listed, or not written out where it is used; a method beside a built
  address that is not the route's own, or that cannot be read at the call (take both
  from `apiTo` then); anything added to a built address but a query or a fragment; a
  cache key whose first word is a route that is not a GET.
- Tests keep their literal addresses on purpose.
- After changing a route: run the generator, as before; the list follows. Running it
  also rewrites the first line of `server/route-policy.ts` and of the two inventory
  tables (the commit and date). When no route changed, leave those three as they were
  (`git checkout --` them).
